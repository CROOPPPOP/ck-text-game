# 게임 시스템 분석 및 개발 계획

## 방향

CK3의 시스템 목록을 복제하는 대신, 인물과 가문을 중심으로 선택이 관계·정치·생계에 이어지는 설계 원칙을 참고합니다. CK3 공식 소개가 강조하는 인물 특성, 가문, 관계, 전쟁, 문화와 종교의 상호작용이 참고점입니다. [공식 소개](https://www.paradoxinteractive.com/games/crusader-kings-iii/about)

이 게임의 고유한 중심축은 **서로 다른 출신에서 시작해 생계를 만들고, 관계와 의무를 통해 지위를 바꾸며, 그 성취와 부담을 다음 세대에 남기는 것**입니다. 이미 구현된 방랑자·집단·성직자·귀족 시작과 승격 경로를 이 경험의 기반으로 삼습니다.

## 설계상 먼저 해결할 기반

### 단일 달력

`timeEngine.ts`는 실시간 일·월·연도를 진행하고, 기존 행동 처리기는 행동마다 계절과 연도를 이동시키던 별도 달력을 갖고 있었습니다. 이 두 방식은 나이·이벤트·자원 변화의 속도를 서로 다르게 만들 수 있습니다. 달력 날짜와 나이의 기준을 실시간 시간 엔진으로 단일화하고, 플레이어 행동은 같은 날짜 안에서 해결되도록 합니다. 턴 번호는 기록·저장용 진행 번호로 유지하며 달력과 혼동하지 않도록 합니다.

월간 이벤트·경제·건설·인구 변화의 규칙도 월간 틱을 기준으로 모으고, 행동 횟수에 따라 월 소득이 중복 누적되지 않는지 테스트해야 합니다.

### 명시적인 상태 계약

AI 응답과 저장 파일 모두 파서 이후 검증이 필요합니다. 필수 필드, 자원 범위, 누락 처리, 세이브 버전을 타입과 검증 함수로 표현합니다. 잘못된 AI 결과는 상태에 적용하지 않고, 이전 유효 상태로 복구하거나 재시도합니다.

### 운영과 비용

BYOK 키는 탭 세션에서만 보관하고, 앱 서버 환경 변수에 둔 공유 키를 인증 없는 API 경로에서 사용하지 않습니다. API 입력 크기와 기본 형태는 서버에서 제한합니다. 공개 서비스 운영 전에는 배포 플랫폼의 요청 제한, 사용량 모니터링, Google API 키 제한을 설정해야 합니다.

## 고유 핵심 루프: 출신에서 가문 유산까지

1. **출신과 제약 선택:** 방랑자, 상단·용병단, 성직자, 귀족 등으로 시작합니다. 각 출신은 자금·보호·권한·의무의 다른 조합을 가집니다.
2. **생계와 당면 문제 해결:** 직업, 의뢰, 영지 수입, 성직 업무 또는 통치로 자원을 마련합니다. 시간 경과로 유지비와 기회가 발생합니다.
3. **관계와 의무 형성:** 후원자, 동료, 상관, 봉신, 경쟁자와의 관계에서 약속·빚·보호·원한이 생깁니다. 관계는 대화창의 숫자에 그치지 않고 행동과 승격 요건을 열거나 닫습니다.
4. **위기와 선택:** 사건은 재정·관계·명성·신앙·스트레스 중 최소 두 영역에 영향을 줍니다. 선택에는 가시적인 대가와 장기 결과가 있습니다.
5. **지위 상승 또는 추락:** 현재 경로 안에서 권한과 책임이 달라지고, 때로는 다른 사회적 경로로 이동합니다. 승격에는 자원뿐 아니라 후원, 정통성, 위험 감수 같은 조건이 따릅니다.
6. **세대 교체와 유산:** 죽음·은퇴·계승 시 칭호와 재산뿐 아니라 주장권, 약속, 빚, 경쟁자, 가문 기억도 넘깁니다. 다음 인물은 이전 선택의 결과를 이어받습니다.

- **성격을 실제 의사결정으로 연결:** 특성은 대사 장식이 아니라 선택 비용, 스트레스, 관계 반응, 승격 조건에 영향을 줍니다. CK3도 인물 특성과 생활 방식이 행동과 계획을 이끄는 점을 강조합니다. [공식 소개](https://www.paradoxinteractive.com/games/crusader-kings-iii/about)

- **시스템 사이에 결과를 전파:** 문화·종교·법·경제는 별도 기능 모음이 아니라 혼인, 통치, 승격, 갈등에 변화를 줍니다. [Royal Court 소개](https://www.paradoxinteractive.com/games/crusader-kings-iii/add-ons/crusader-kings-iii-royal-court)
- **기능 수보다 반복 가능한 이야기:** 여행·궁정·종교·전쟁의 모든 세부 기능을 먼저 구현하지 말고, 기존 상태와 관계를 근거로 다른 선택을 하게 만드는 기능부터 추가합니다.

## 단계별 구현 순서

### 0단계 — 신뢰 가능한 시뮬레이션 기반

- [x] 달력 날짜의 단일 기준을 실시간 시간 엔진으로 정하고, 행동 처리에서 날짜·나이를 임의로 진행시키지 않습니다.
- [ ] 월간 자원·인구·이벤트·건설 변화를 하나의 틱 경계로 모읍니다.
- [ ] 게임 상태와 AI 결과를 검증하는 스키마 및 실패 복구 정책을 추가합니다.
- [x] BYOK 키를 세션 범위로 저장하고 요청 입력 크기를 제한합니다.
- [x] 테스트 실행 명령, 타입 검사 명령, CI 워크플로를 추가합니다.

**완료 기준:** 동일한 날짜와 상태의 행동은 달력을 건너뛰지 않고, 한 달 경과는 월간 효과를 정확히 한 번만 적용합니다. 비정상 AI 응답과 오래된 저장 파일을 안전하게 거부하거나 복구합니다.

### 1단계 — 세로형 플레이 시제품

- 네 가지 시작 경로에서 1년 이상 플레이 가능한 짧은 캠페인을 구성합니다.
- 각 경로마다 생계 수단, 핵심 관계, 대표 위기, 승격 목표를 최소 하나씩 연결합니다.
- 행동·월간 이벤트·자원·관계 변화가 연대기에 남게 합니다.
- 기존 시스템 중 핵심 흐름과 연결되지 않는 기능은 우선순위를 낮춥니다.

**완료 기준:** 경로에 따라 최선의 전략이 달라지고, 플레이어가 사건을 해결한 결과가 승격과 다음 사건에 영향을 줍니다.

### 2단계 — 관계와 의무, 성격 기반 선택

- 관계를 `관계 점수 + 관계 유형 + 만료/상태 + 조건`으로 표현합니다.
- 후원, 빚, 약속, 보호, 원한을 사건·협상·승격 조건에 연결합니다.
- 성격과 스트레스는 행동의 비용·반응·실패 위험에 영향을 줍니다.
- AI는 서사 문장만 작성하고 상태 변화는 명시적인 규칙과 선택 결과로 적용합니다.

**완료 기준:** 저장 후 다시 불러와도 관계 의무와 스트레스가 유지되고, 그 값이 실제 선택지에 영향을 줍니다.

### 3단계 — 계승과 사회적 이동

- 상속 재산·칭호와 함께 주장권, 약속, 빚, 가문 기억을 계승시킵니다.
- 승격과 몰락 경로를 시작 신분별로 균형 조정합니다.
- 가계도와 과거 생애 기록에서 다음 세대가 이어받은 효과를 확인할 수 있게 합니다.

**완료 기준:** 세대 교체가 단순한 캐릭터 교체가 아니라 새로운 강점과 해결 과제를 만듭니다.

### 4단계 — 영지·경제·군사·문화 확장

- 월 수입·유지비·인구·공사 시간을 단일 시간 기준과 맞춥니다.
- 관계와 세력 갈등이 협상·봉기·전쟁으로 이어지게 합니다.
- 문화·종교 변화는 출신별 지위 상승, 혼인, 통치와 연결합니다.
- 앞선 단계의 플레이 흐름에 기여하는 전쟁·여행·궁정 기능을 우선 도입합니다.

**완료 기준:** 추가 시스템이 기존 선택지와 결과에 변화를 주며, 독립된 장식 메뉴로 남지 않습니다.

## 자동화 검증 목표

- 시간 엔진: 일·월·연도 경계, 배속, 일시정지, 행동 시 달력 불변.
- 경제: 월간 수입/유지비가 월간 틱에서만 한 번 반영되는지.
- 상태 계약: 잘못된 타입·범위·누락 필드의 거부와 복구.
- 저장: 버전 업그레이드, 손상 데이터, 내보내기/가져오기.
- 시스템 통합: 관계 변화가 사건·승격 요건에 영향을 주고, 결과가 연대기와 세대 교체까지 지속되는지.

## 후속 보강 계획 — 실행 순서

### 우선순위 1: 월간 틱의 단일 진입점

**목표:** 시간 엔진이 월을 넘길 때만 경제·건설·인구·월간 사건을 한 번 실행합니다.

1. 기존 월간 수입, 유지비, 건설 진행, 인구 변화, 이벤트 호출 위치를 목록화하고 중복 경로를 제거합니다.
2. `processMonthlyTick(state)` 같은 순수 엔진 함수를 만들고 월 경계에서만 호출합니다.
3. 행동 처리에서는 월 수입을 지급하지 않고, 행동의 직접 비용과 효과만 적용합니다.
4. 월 경계를 넘지 않는 행동 여러 번과 정확히 한 달 경과를 비교하는 회귀 테스트를 추가합니다.

**완료 기준:** 행동 횟수와 무관하게 한 달의 경제 효과가 정확히 한 번 반영되고, 정지·배속·오프라인 복귀에서도 월 경계를 건너뛰거나 중복 처리하지 않습니다.

### 우선순위 2: 상태·저장·AI 응답 계약

1. 저장 상태와 AI 응답의 런타임 스키마를 정의하고 필수 필드, 범위, 배열 크기, 문자열 길이를 검증합니다.
2. 저장 파일에 `schemaVersion`을 두고 버전별 마이그레이션 함수를 둡니다.
3. 잘못된 응답을 상태에 부분 적용하지 않도록 처리 단계를 검증 후 커밋 방식으로 바꿉니다.
4. 오래된 저장, 손상된 JSON, 필드 누락, 범위 초과 및 AI 응답 실패 복구 테스트를 추가합니다.

**완료 기준:** 잘못된 데이터는 게임 상태를 망가뜨리지 않으며, 복구할 수 없는 세이브는 원인을 사용자에게 알리고 직전 유효 저장을 보존합니다.

### 우선순위 3: 세로형 플레이 루프와 출신별 균형

1. 방랑자·집단·성직자·귀족별 1년짜리 플레이 시나리오를 작성합니다.
2. 각 시나리오에 생계, 관계 의무, 위기, 지위 목표, 실패/회복 경로를 하나씩 연결합니다.
3. 시작 자원과 선택별 비용을 계측해 특정 출신이나 행동이 압도하지 않는지 조정합니다.
4. 결과를 연대기에서 검토하고, 자동 플레이 시나리오로 핵심 진행 경로를 검증합니다.
